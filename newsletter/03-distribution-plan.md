# 03. 배포 계획

## 1. 배포 채널 (후보)

| 채널 | 장점 | 단점 | 자동화 용이성 |
|---|---|---|---|
| 사내 메일 (HTML 뉴스레터) | 공식적, 보관·검색 쉬움 | 메일함에 묻힐 수 있음 | ○ (SMTP/메일 API) |
| 사내 메신저 (Slack / Teams / 잔디 등) | 즉시 읽힘, 반응·댓글로 피드백 | 긴 글은 가독성 떨어짐 | ◎ (Webhook) |
| 그룹웨어 게시판 / 노션·컨플루언스 | 아카이브로 좋음 | 능동적으로 찾아와야 함 | △~○ (API 여부에 따라) |

**권장 조합**
- **본문**: 사내 메일 (또는 노션/웹 페이지) — 원문 아카이브
- **알림**: 메신저 채널에 "이번 호 핵심 3줄 + 링크" — 도달률 확보
- 주간 캘린더 단신(Phase 2 이후)은 **메신저 단독**으로 충분

## 2. 발행 일정 (권장안 기준)

| 구분 | 발행일 | 대상 기간 | 마감 |
|---|---|---|---|
| 월간 본편 | 매월 첫째 주 월요일 오전 | 해당 월 행사 + 직전 월 업계 소식 | 직전 주 목요일 초안, 금요일 검수 |
| 주간 캘린더 단신 (Phase 2~) | 매주 월요일 오전 9시 | 당주 월~일 | 자동 생성 → 담당자 확인 |

### 월간 본편 제작 타임라인 (수동 단계)
| 시점 | 할 일 | 담당 |
|---|---|---|
| 상시 | 기사·제보 링크를 `issues/YYYY-MM.md` 스크랩 영역에 모으기 | 편집 담당, 전 직원 제보 |
| D-7 (월) | venue 캘린더 수집 → 섹션 3 표 작성 | 편집 담당 |
| D-5 (수) | 섹션 1·2·4 작성, 섹션 5 초안 | 편집 담당 |
| D-4 (목) | 운영팀에 자사 수행 행사 표시 확인 요청 | 편집 담당 → 운영팀 |
| D-3 (금) | 검수 (사실 확인, 대외비 포함 여부) | 검수자 |
| D-day (월) | 발송 + 메신저 공지 | 편집 담당 |

## 3. 역할 (R&R)

| 역할 | 하는 일 | 담당 (미정) |
|---|---|---|
| 편집장 / 오너 | 방향성, 섹션 5(시사점) 최종 문구 | |
| 편집 담당 | 수집·작성·발송 | |
| 검수자 | 사실관계, 대외비·민감 정보 체크 | |
| 섹션 기여자 | 영업(경쟁사 제보), 운영(자사 행사), 개발(기술 트렌드 코멘트) | |

> 1인 운영으로 시작하더라도 **검수자는 별도로 1명** 두는 것을 권장 (경쟁사 관련 서술 리스크).

## 4. 성과 지표 (KPI)

| 지표 | 측정 방법 | 초기 목표 (3개월) |
|---|---|---|
| 도달 | 메일 오픈율 / 메신저 읽음 수 | 오픈율 60% 이상 |
| 반응 | 메신저 리액션·댓글, 제보 건수 | 호당 제보·의견 3건 이상 |
| 활용 | 뉴스레터발 개선 아이디어·안건 수 | 분기 1건 이상 |
| 만족도 | 분기 1회 3문항 설문 | "업계 파악에 도움된다" 70% 이상 |

## 5. 운영 규칙
- 경쟁사 관련 내용은 **공개된 정보만**, 출처 링크 필수
- 고객사·계약 관련 대외비는 원고에 기재 금지
- 외부 기사 본문은 **전재하지 않고 요약 + 링크**로 처리 (저작권)
- 발행본은 `issues/`에 보관해 아카이브로 활용

## 6. 파일럿 계획
1. 2026년 11월호(또는 12월호)를 **파일럿**으로 수동 제작
2. 소규모(팀장급 또는 희망자 10명 내외)에게 먼저 배포 → 피드백
3. 피드백 반영 후 전사 배포 시작, 2~3호 운영 후 주기·채널 확정
